Facebook Worker Integration — Progress Notes

Date: 2026-02-13

Summary:
- Implemented a Cloudflare Worker proxy at `cloudflare-worker/worker.js` to forward Graph API calls for:
  - `/api/facebook/insights` -> GET page insights
  - `/api/facebook/pages` -> GET /me/accounts
  - `/api/facebook/me` -> token inspection
- Worker includes CORS preflight handling and supports passing user tokens via `Authorization: Bearer <token>` or using a bound secret `FB_PAGE_ACCESS_TOKEN`.

Client-side work:
- Added `src/lib/facebook.ts` helpers: `fetchFacebookInsights`, `fetchFacebookPages`, `fetchFacebookMe`.
- Wired `src/pages/Dashboard.tsx` to call the worker and render metrics via `PerformanceChart` when available.
- Extended `src/pages/Settings.tsx` with inputs for `fbWorkerUrl`, `fbUserToken`, `fbPageId`, and `fbAccessToken`; added UI to `Fetch Pages` and show raw worker responses for debugging.
- Added token test button (`/api/facebook/me`) to inspect token owner and show raw response.

Troubleshooting performed:
- Verified worker receives requests and returns responses (worker-level 200). Browser CORS issues were resolved by adding Access-Control-Allow-Origin and handling OPTIONS.
- When user-tested a token, `/api/facebook/me` returned a valid owner (`{"id":"3505586092912626","name":"Shane Hayes"}`) while `/api/facebook/pages` returned `{"data":[]}`.
- Conclusion: token is valid but Facebook returned no pages. Likely causes:
  - The user is not an admin of any Facebook Page.
  - The token lacks required scopes (e.g., `pages_show_list`, `pages_read_engagement`).
  - The token was generated by an app without appropriate permissions or app in dev mode without access.

Current action taken:
- Paused the Facebook settings UI in the app and marked the feature "Coming Soon" in `src/pages/Settings.tsx` (UI greyed out, actions disabled).

Next recommended steps for the user:
1. Using Graph API Explorer, generate a User Access Token with scopes: `pages_show_list`, `pages_read_engagement` (and `pages_manage_posts` if posting is needed). Call `GET /me/accounts?fields=id,name,access_token,perms`.
2. If `data: []` persists in Graph Explorer, confirm Page Roles in Page Settings and ensure your account is an admin/editor of the Page.
3. Once a Page Access Token is available, add it to Settings `Facebook Page Access Token` and re-enable the integration.
4. For production, bind the page access token as a Cloudflare Worker secret (`FB_PAGE_ACCESS_TOKEN`) instead of sending tokens from the client.
